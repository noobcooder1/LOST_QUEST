# LOST QUEST 프론트엔드 프로토타입

잃어버린 소중한 것, 다시 만나는 여정. 학교 팀 프로젝트에서 화면 디자인과 이용 흐름을 검증하기 위한 한국어 웹 애플리케이션입니다. React + TypeScript + Vite, Tailwind CSS, React Router를 사용합니다.

물품 검색·등록·AI 매칭·반환·보상 체험은 브라우저의 가상 데이터로 독립적으로 동작합니다. 선택적으로 Spring Boot 백엔드의 연결 상태만 확인할 수 있으며, 현재 물품·회원·반환 데이터는 서버와 연동하지 않습니다. 백엔드 구성과 실행 방법은 [프로젝트 루트 README](../README.md)를 참고하세요. 실제 공공데이터·AI·인증·AWS 배포는 포함하지 않습니다.

## 실행

Node.js 22.12 이상을 권장합니다. 구현 환경은 Node.js 24입니다.

```bash
cd frontend
npm install
npm run dev
```

브라우저에서 **http://127.0.0.1:5173**에 접속합니다. 개발 서버 종료는 실행 터미널에서 `Ctrl+C`입니다. 포트 5173이 사용 중이면 기존 개발 서버를 종료하거나 `npm run dev -- --port 5174`로 실행하세요.

```bash
npm run build     # TypeScript 검사 + dist/ 정적 빌드
npm run preview   # 빌드 결과 로컬 미리보기
npm test          # 반환 상태, 경험치, 저장 데이터, 매칭, API 연결 처리 테스트
```

Windows PowerShell의 실행 정책이 npm.ps1을 막으면 `npm.cmd install`, `npm.cmd run dev`처럼 사용합니다. 처음 패키지를 설치할 때만 인터넷 연결이 필요하며, 실행 중 물품·AI 데이터를 외부에서 가져오지 않습니다. 폰트와 예시 이미지도 로컬 파일입니다.

## 선택 사항: 백엔드 연결 확인

프론트엔드 디렉터리에서 `.env.example`을 `.env.local`로 복사합니다. Windows PowerShell에서는 다음과 같이 실행합니다.

```powershell
Copy-Item .env.example .env.local
```

```dotenv
VITE_API_BASE_URL=http://localhost:8080
```

백엔드는 [루트 실행 안내](../README.md)에 따라 별도 터미널에서 실행하고 Vite 개발 서버를 다시 시작합니다. 페이지 맨 아래의 **백엔드 연결 확인 → 연결 확인** 버튼을 누르면 `GET http://localhost:8080/api/health` 요청을 보냅니다. API 주소는 서버의 기본 주소이며 `/api/health`는 클라이언트가 붙입니다. 마지막 `/`가 있어도 처리합니다. Vite 환경변수는 시작·빌드 시 반영되므로 변경 후 개발 서버 재시작 또는 재빌드가 필요합니다.

- 성공 응답은 JSON `{ "status": "OK", "service": "LOST QUEST API" }`이며 두 값을 모두 검증합니다.
- **설정 전 / 대기 / 확인 중 / 성공 / 실패** 상태를 표시합니다. HTTP 오류, 다른 형식의 응답, 네트워크·CORS 오류와 5초 제한 시간 초과를 구분해 안내합니다.
- 환경변수가 없으면 설정 방법만 표시하고 요청하지 않습니다. 설정했어도 페이지를 여는 것만으로 자동 호출하거나 주기적으로 조회하지 않으며 버튼을 눌렀을 때만 확인합니다.
- 서버가 꺼져 있어도 기존 가상 물품·반환 기능은 그대로 사용할 수 있습니다. 연결 확인은 `localStorage`나 로그인 상태를 바꾸지 않으며 인증 쿠키를 전송하지 않습니다.
- `VITE_` 변수는 브라우저 번들에 공개됩니다. API 키·비밀번호·인증 토큰은 넣지 마세요. `.env.local`은 Git에 올리지 않습니다.

연결 오류가 나면 백엔드 실행 여부, 포트와 `VITE_API_BASE_URL`, 백엔드의 CORS 허용 주소를 확인하세요. 프론트엔드 기본 주소는 `http://127.0.0.1:5173`입니다. 브라우저 주소의 호스트나 포트를 바꾸었다면 백엔드 CORS 설정도 맞춰야 합니다.

| 전국 검색 | `/search` | 검색어, 자체 등록·공공데이터 구분, 유형·지역·카테고리·기간 필터, 날짜 정렬, 빈 결과 안내 |

| 물품 상세 | `/items/:id` | 정보·위치 탭, 자체 등록 습득물 반환 요청, 공공 물품 공식 사이트 안내 |
| 반환 진행 | `/returns/:id` | 비공개 특징 확인, 승인 대기, 테스트 QR, 관리자 최종 확인, 보상 결과 |
| 마이페이지 | `/mypage` | 경험치·레벨·진행률·업적, 등록·반환·알림 탭, 읽음 처리, 로그아웃, 체험 초기화 |
| 관리자 | `/admin` | 요청 필터, 검토·승인·반려, QR 인증 후 반환 완료와 경험치 지급 |
| 이용 안내 | `/guide` | 등록부터 반환까지 단계별 체험 방법 |

PC 상단 내비게이션과 모바일 하단 내비게이션을 제공하며, 화면 폭에 따라 카드·폼·매칭·관리자 배치가 변경됩니다. 링크와 폼에는 키보드 포커스, 레이블, 오류 메시지를 제공하고 초기화·반려는 확인 대화상자를 사용합니다.

## 검은색 지갑으로 전체 흐름 체험하기

1. 메인에서 **잃어버렸어요**를 누르고 **테스트 계정으로 시작하기 → 테스트 계정으로 로그인**을 선택합니다. 실제 이메일·비밀번호는 입력하지 않습니다.
2. 기본 선택된 **검은색 지갑**을 사용합니다. **AI 분석 시뮬레이션 실행 → 이 정보로 입력하기**를 누릅니다. 기본 날짜 `2026-09-16`, 지역 `서울`, 장소 `서울 성동구 서울숲역`으로 진행하면 재현하기 쉽습니다.
3. **다음 단계**에서 상세 정보를 확인하고 **분실물 등록하기**를 누릅니다. 등록 보상 `+10 XP`가 적용됩니다.
4. **AI 자동 매칭 체험**에서 **검정 가죽 반지갑**(기본 조건에서 92점, ID `found-wallet-1`)의 상세 페이지를 엽니다.
5. **내 물건이라면, 반환 요청하기**를 누릅니다. 비공개 특징의 테스트 정답은 **파란색**입니다. 다른 답변은 오류 안내가 나오며 다음 단계로 진행되지 않습니다.
6. **소유자 확인하기 → 관리자 화면에서 승인하기**로 이동하여 **요청 승인**을 누릅니다.
7. **반환 진행 보기 → 테스트 QR 인증하기**를 누릅니다. QR은 테스트 요청 ID만 담으며 실제 신원 확인이나 물품 반환에 사용할 수 없습니다.
8. **관리자 화면에서 반환 완료하기 → 반환 완료 · +50 XP**를 누릅니다.
9. 마이페이지에서 누적 **380 XP**(초기 320 + 등록 10 + 반환 50), 반환 **4건**(초기 예시 3 + 체험 1), **친절 수집가** 업적 해제를 확인합니다. 실제 요청 내역은 이번 체험에서 생성한 기록만 표시됩니다.

레벨은 `floor(누적 XP / 100) + 1`, 다음 레벨 진행률은 `누적 XP % 100`입니다. 새로고침 후에도 물품·반환 상태·보상은 유지되며, 로그인 상태는 해제되므로 테스트 로그인을 다시 누르면 됩니다. 반복 체험은 **마이페이지 → 체험 초기화**에서 확인 후 시작합니다.

### 반환 상태 규칙

```text
pending → owner_verified → approved → qr_verified → completed
요청      특징 확인         관리자 승인  테스트 QR      최종 완료 (+50 XP)
```

관리자는 진행 중 요청을 반려할 수 있으며 반려된 요청에는 보상을 지급하지 않습니다. 완료·반려 상태는 되돌리지 않습니다. 승인 전 QR 인증, QR 전 최종 완료, 반복 클릭의 중복 지급을 막습니다. 같은 습득물이나 같은 분실물에 진행 중 요청을 중복 생성하지 않습니다. 반환 완료 시 연결된 분실물과 습득물 모두 반환 완료로 갱신됩니다.

## 데이터와 개인정보

- 가상 지갑·이어폰·스마트폰·백팩·열쇠·카메라 등 10개 초기 물품을 제공합니다.
- `localStorage` 키는 `lost-quest-demo-v1`이며 `{ version: 1, data: ... }` 구조입니다.
- 테스트 물품 정보, 반환 상태, 고정 프로필, XP, 알림을 저장합니다. 손상되거나 스키마에 맞지 않는 데이터는 기본 데모로 복구하고 안내합니다. 저장 공간 부족·저장 제한은 경고를 표시하고 메모리 체험을 유지합니다.
- 로그인 여부는 메모리에만 둡니다. 실제 이메일·비밀번호·인증 토큰은 수집하거나 저장하지 않습니다. 회원가입은 고정된 테스트 계정으로 시작하는 화면 시뮬레이션입니다.
- PNG/JPEG/WebP 사진은 최대 2MB이며 서버에 전송하지 않습니다. 선택한 사진은 현재 실행 중에만 표시하고, 새로고침하면 종류별 예시 일러스트로 대체합니다.
- 소유자 확인 답변은 모든 체험에서 `파란색`으로 고정합니다. 실제 소유자 비밀 정보를 수집하지 않습니다.
- 자유 입력란에는 **가상의 물품 정보만** 입력하세요. 입력한 물품명·설명·장소는 저장되며, 개인정보 자동 탐지 기능은 없습니다. 실제 연락처·주거지·신분증 정보 등을 입력하지 않도록 화면에 안내합니다.
- 브라우저별 독립 체험입니다. 다른 브라우저나 사용자와 데이터가 동기화되지 않으며, 동시 탭 편집의 충돌 처리는 구현하지 않았습니다.

## AI·공공데이터 시뮬레이션

사진 분석 버튼은 선택한 샘플 또는 입력된 종류·색상을 제안하는 시뮬레이션입니다. 업로드한 이미지의 픽셀을 분석하지 않습니다. 매칭은 같은 카테고리의 습득물에 대해 색상·지역·시간 차이를 계산하는 결정적 규칙입니다. 결과는 소유권 확인이나 실제 AI의 확률이 아닙니다. 관련 화면에 시뮬레이션 안내를 표시합니다.

공공데이터 물품도 모두 가상입니다. 외부 물품의 반환 버튼 대신 경찰청 LOST112 공식 홈페이지 안내 링크를 제공합니다. 링크는 실제 예시 물품 상세와 연결되지 않습니다. API 키·전화번호·실제 기관 접수번호는 필요하지 않습니다.

## 폴더 구조

```text
frontend/
├── public/
│   ├── favicon.svg
│   ├── fonts/               # Pretendard 폰트와 OFL 라이선스
│   └── images/              # 직접 작성한 물품 SVG 일러스트
├── src/
│   ├── components/          # Layout, Logo, ItemCard, ApiHealthStatus
│   ├── context/             # AppProvider, useApp, 메모리 세션
│   ├── data/seed.ts         # 초기 데이터와 종류별 이미지
│   ├── pages/               # 기능별 페이지와 전용 스타일
│   ├── services/
│   │   ├── apiClient.ts     # 선택적 백엔드 health 확인·응답 검증·제한 시간
│   │   ├── apiClient.test.ts
│   │   ├── demoStore.ts     # 등록·반환 상태 전이와 보상
│   │   ├── matching.ts      # 매칭 규칙과 추천 근거
│   │   ├── storage.ts       # 저장 필드 제한·검증·복구
│   │   └── demoStore.test.ts
│   ├── types.ts            # 물품·요청·프로필·알림 타입
│   ├── vite-env.d.ts        # 공개 API 환경변수 타입
│   ├── App.tsx             # 라우팅과 페이지 지연 로딩
│   ├── main.tsx            # React 진입점
│   └── styles.css          # Tailwind와 공통 반응형 디자인
├── index.html
├── .env.example            # 선택적 API 주소 예시 (비밀값 없음)
├── vite.config.ts
├── tsconfig.json
└── package.json
```

상태 규칙은 `services`의 순수 함수로 분리하고 화면에서는 `useApp()`을 사용합니다. `apiClient.ts`는 현재 연결 상태만 확인하는 독립 경계입니다. 후속 물품 REST 연동 시 서비스 호출과 Context 내부 구현을 교체하고 페이지 구성은 유지할 수 있습니다. 프론트엔드에는 외부 상태 관리 라이브러리를 추가하지 않았습니다.

| AI | 실제 이미지 업로드·임베딩·유사도 모델, 지역·시간 가중치, 모델 평가와 불확실성 설명 |
| QR | 서버 발급·만료·서명·일회 사용, 소유자 및 관리자 권한 검증, 실제 스캐너 |
| 알림 | 서버 이벤트, 폴링 또는 푸시, 사용자별 읽음 상태 |
| PWA | 앱 아이콘·manifest·서비스 워커·오프라인 캐시·설치 흐름·업데이트 정책 |

현재는 PWA를 설치 가능한 앱으로 등록하거나 서비스 워커를 켜지 않았습니다. Vite 진입점·분리된 정적 자산·모바일 레이아웃·theme-color를 기반으로 후속 단계에서 추가할 수 있습니다. 배포 시에는 React Router 경로가 `index.html`로 돌아오는 SPA fallback 설정이 필요합니다.

## 검증

`npm test`는 전체 반환 순서, 잘못된 답변, 건너뛰기, 중복 보상·중복 요청 방지, 반려 후 재요청, 공공 물품 반환 차단, 등록 XP, 손상 저장 데이터, 업로드 사진·인증 필드 제외, 결정적 매칭을 확인합니다. `apiClient.test.ts`는 fetch를 대체하여 성공 응답, URL 끝 슬래시, 미설정 시 요청 차단, 잘못된 주소, HTTP 오류, 잘못된 JSON·서비스 응답, 네트워크 오류, 제한 시간에 따른 요청 중단을 검증합니다. 이 단위 테스트에는 실행 중인 백엔드가 필요하지 않습니다. `npm run build`로 타입 검사와 실제 배포용 번들 생성도 검증합니다.

수동 확인 항목: 데스크톱·모바일 화면, 테스트 로그인과 원래 경로 복귀, 사진/샘플 등록, 검색 필터와 빈 결과, 매칭 정렬, 전체 반환 절차, 알림 읽음, 새로고침 후 데이터 유지, 로그아웃, 체험 초기화, 외부 물품 안내.

2026-09-23 기준 TypeScript·프로덕션 빌드와 자동 테스트 **12개**가 통과했습니다. 브라우저에서 검은색 지갑 등록 → 매칭 → 잘못된/올바른 소유자 답변 → 관리자 승인 → QR → 최종 반환 → 380 XP·업적 갱신, 새로고침 후 기록 유지, 알림 읽음, 회원가입 체험, 습득물 등록, 복합 지역·종류 필터, 외부 물품 안내를 확인했습니다. 데스크톱과 390px·320px 모바일 화면도 확인했습니다. 카메라 스캔이나 실제 이미지 인식의 검증을 의미하지 않습니다.
