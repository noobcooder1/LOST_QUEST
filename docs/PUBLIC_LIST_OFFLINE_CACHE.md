# 공개 목록 연결 상태와 IndexedDB 캐시

2026-10-13 공개 목록 캐시 구현·검증 보고서. 초기 구현·리뷰 수정 단계에서는 Git 커밋·푸시·PR 생성·Sites 재배포를 하지 않았습니다. 이후 사용자 승인으로 기존 Sites를 버전 8(소스 커밋 `5916fc62be4f9823e268c2dad96982841c9120f6`)로 업데이트했습니다. 기존 ngrok 주소·Sites 설정·Spring Security·JWT·DB 스키마와 물품/반환 비즈니스 로직은 유지했습니다.

## 코드 분석과 적용 범위

`SearchPage`는 자체 등록 전체 목록과 경찰청 페이지 목록을 합쳐 검색합니다. 자체 등록은 원래부터 브라우저에서 검색·필터·정렬을 적용하고, 경찰청은 서버 검색 조건과 더 보기 페이지를 사용합니다. 기존 구조를 유지하면서 자체 등록 분실물/습득물까지 분리하여 네 출처가 독립적으로 성공·실패하도록 했습니다.

| 공개 목록 | 실제 GET API | 저장·복원 단위 |
| --- | --- | --- |
| 자체 등록 분실물 | `/api/lost-items` | 전체 목록 스냅샷 |
| 자체 등록 습득물 | `/api/found-items` | 전체 목록 스냅샷 |
| 경찰청 분실물 | `/api/public-items/lost` | 실제 검색 조건·페이지·크기 |
| 경찰청 습득물 | `/api/public-items/found` | 실제 검색 조건·페이지·크기 |

네 종류 모두 전국 통합 검색(`/search`)에 적용했습니다. `AppContext`의 공개/개인 활동 로딩은 변경하지 않았으며, 캐시 항목을 인증·매칭·알림·반환에 사용하는 전역 데이터에 섞지 않습니다. 마이페이지·내 등록 목록·관리자·반환·상세 GET은 캐싱하지 않습니다.

`ItemDetailPage`는 URL id를 확인하고 상세 API를 직접 호출합니다. 이 동작을 유지합니다. 저장된 목록 카드는 `<article>`로 표시하여 상세·작업으로 이동할 수 없고, 온라인 카드는 기존 `<Link>`를 유지합니다. 전역 내비게이션과 인증·쓰기 요청은 기존 동작입니다. 캐시 기능이 등록·반환을 오프라인으로 수행하거나 성공한 것처럼 보이지 않습니다.

## 상태와 재연결

| 상태 | 화면 동작 |
| --- | --- |
| 최신 데이터 | 실제 API 응답 표시, 마지막 성공 동기화 시각 표시, 캐시 갱신 |
| 저장된 데이터 | 연결 장애와 오래된 데이터임을 안내, 동기화 시각·다시 연결 버튼, 읽기 전용 카드 |
| 서버 연결 불가 | 동일 조회 조건의 유효한 캐시 없음 안내, 다시 연결 버튼, 등록 권유 숨김 |
| 조회 요청 오류 | 인증·권한·입력 등 오류 표시, 캐시로 덮어쓰지 않음 |

사용자가 다시 연결을 누르면 해당 출처의 GET만 다시 호출합니다. 성공하면 최신 데이터로 교체하고 캐시 및 시간을 갱신합니다. 경찰청 재연결은 첫 페이지에서 새 목록을 시작합니다. 동기화 시각은 `Asia/Seoul` 기준입니다. 브라우저 `navigator.onLine`에 따라 요청을 생략하지 않습니다.

리뷰 후 M1 수정: 경찰청 2페이지 이상 추가 조회 실패는 해당 페이지의 오류·재시도 상태로만 표시합니다. 기존 목록·최신/저장 데이터 상태·성공한 페이지 번호는 유지하고, 재시도 성공 시 중복 없이 추가합니다. 추가 페이지 실패로 전체 목록을 캐시로 교체하지 않습니다. L1 수정: 첫 페이지 캐시가 없으면 뒤 페이지를 단독 복원하지 않고, 페이지가 누락되면 그 앞의 연속된 구간까지만 복원합니다. 기존 검색 조건 변경 및 요청 버전 검증도 유지합니다.

`NETWORK_ERROR`, `TIMEOUT`, HTTP 500/502/503/504만 대체 대상으로 분류합니다. 알려진 ngrok 개발 호스트에서 HTML 응답에 `ERR_NGROK_*`가 들어간 경우에도 API 경로 장애로 분류하며, HTML은 저장하지 않습니다. 400/401/403, 일반 404, 409/422/429나 일반 응답 형식 오류는 캐시 대체 대상이 아닙니다. 경찰청 하나의 실패를 다른 출처의 오프라인 상태로 전파하지 않습니다. POST·PUT·DELETE에는 캐시 대체·재전송·오프라인 큐가 없습니다.

## IndexedDB 구조·저장 정책

- 별도 DB `lost-quest-public-lists`, 버전 `1`, object store `lists`, keyPath `key`.
- 키: `SHA256([버전, API 기본 주소, 목록 종류, 정규화된 실제 서버 검색 조건, 페이지 크기]) + ':' + 페이지`. 원문 검색어를 키나 별도 필드에 저장하지 않습니다.
- 경찰청 키워드 모드는 서버와 동일하게 앞뒤 공백을 제거하고 50자까지 사용하며 날짜·코드 조건을 제외합니다. 날짜 모드는 지역·종류·세부 종류 및 습득물 색상을 구분합니다.
- 자체 등록 API는 검색 조건이나 서버 페이지를 받지 않으므로 종류별 `scope: all`, 페이지 `1`, 크기 `0`의 전체 스냅샷입니다. 화면에서 조건을 바꾸면 해당 전체 요약에 기존 필터를 다시 적용합니다. 필터마다 전체 목록을 중복 저장하지 않습니다.
- 레코드: `key`, `version`, `kind`, `items`, `page`, `totalCount`, `totalPages`, `createdAt`, `updatedAt`, `bytes`.
- 물품 저장 필드: 공개 id·제목·유형·종류·색상·발생 날짜·지역·이미지 URL/경로·저장 당시 상태·출처. 정확한 장소는 저장하지 않고 지역만 표시합니다. 상세 설명은 빈 값입니다.
- `userId/ownerId`, 소유자 질문·답변, 전화번호, 상세 facts, 프로필, 세션, JWT·비밀번호를 저장하지 않습니다. 공개 제목 등에서도 표준 이메일·전화번호 패턴을 제거합니다. 자유 입력 제목의 모든 이름·개인정보를 자동 식별한다는 보장은 없습니다.
- 이미지는 서버의 검증된 상대 이미지 경로 또는 검증된 경찰청 URL만 저장하며, Blob/data URL을 저장하지 않습니다. 이미지 요청 실패 시 기존 종류별 SVG 대체 이미지로 표시합니다.
- 최대 **40개 레코드**, 합계 **5 MiB**, 레코드당 **512 KiB**, 목록당 **2,000개 물품**. 용량은 JSON UTF-8 직렬화 바이트 기준이며 IndexedDB 내부 관리 공간은 별도입니다. 한도를 넘는 목록은 부분 저장하지 않고 저장을 생략합니다. 온라인 전체 응답은 계속 표시하며 저장 실패 안내를 제공합니다.
- TTL **7일**. 읽기·저장 시 만료/잘못된 레코드를 정리하고, 개수·용량 한도를 넘으면 마지막 갱신이 오래된 레코드부터 제거합니다. 읽었다는 이유로 성공 동기화 시각을 갱신하지 않습니다.
- 저장과 정리는 readwrite transaction으로 수행합니다. 첫 페이지 갱신 시 같은 조건의 이전 다음 페이지 캐시를 제거합니다. 장애 시 첫 페이지부터 연속해서 실제 조회·저장된 경찰청 페이지들을 복원하며, 마지막 동기화는 복원한 페이지 중 가장 오래된 시각입니다.
- IndexedDB와 Web Crypto가 필요합니다(현 환경의 HTTPS와 localhost 지원). 사용 불가·권한·Quota·트랜잭션 오류는 API 오류로 전파하지 않습니다. DB 열기·트랜잭션은 각각 2초 제한입니다. API가 정상이라면 온라인 화면은 정상 동작합니다.

## 로컬 검증

자동 테스트는 네트워크 성공·장애 응답을 모킹하고 `fake-indexeddb`를 실제 트랜잭션처럼 사용합니다. 개발 DB나 실행 중인 서버를 종료·변경하지 않습니다. React UI 테스트는 저장 후 재마운트하여 메모리가 아닌 IndexedDB로 복원하는지 확인합니다.

검증 항목: 정상 조회/캐시 생성, 빈 결과 갱신, 연결 장애/시간 초과, 캐시 없는 첫 방문, 다른 종류/검색/필터/페이지/서버 구분, 마지막 동기화, 재연결, 7일 만료, 40개·5 MiB 한도, 저장소 사용 불가/Quota, 401/403/400 등 대체 금지, ngrok HTML 저장 금지, 경찰청만 실패, 개인 API/상세/쓰기 비저장 및 자동 재전송 없음. 기존 로그인·등록·수정·삭제·반환 테스트도 전체 프론트엔드 테스트에서 확인합니다.

```powershell

npm.cmd test
npm.cmd run build
```

전체 로컬 프론트엔드 테스트 **32개 파일·357개 통과**, TypeScript·Vite 프로덕션 빌드 성공. 초기 캐시·조회·UI 테스트 34개에 M1·L1 회귀 검증을 추가했습니다. 일부 기존 jsdom 테스트의 `window.scrollTo` 미구현 안내는 비실패 메시지입니다. 로컬 전체에는 별도 미커밋 Layout 테스트 3개가 포함되어 있으므로 해당 파일을 제외한 캐시 커밋의 테스트 수는 354개입니다. 실제 브라우저에서 ngrok/Spring Boot를 종료했다가 켜는 수동 체험은 자동 검증 범위에 포함되지 않습니다.

## 직접 시연

1. MySQL과 Spring Boot를 평소처럼 실행합니다. `frontend/.env.local`을 덮어쓰지 말고 기존 API 주소를 사용합니다. `npm.cmd run dev` 후 로컬 React의 `/search?source=community`를 엽니다.
2. 두 목록의 **최신 데이터**와 동기화 시각을 확인합니다. DevTools → Application → IndexedDB → `lost-quest-public-lists` → `lists`에서 레코드를 확인합니다.
3. 경찰청도 시연하려면 `/search?source=public&q=지갑`을 조회하고 더 보기로 다음 페이지를 불러옵니다. 공공데이터 키와 상류 API가 정상인 개발 서버가 필요합니다.
4. `.env.local`이 localhost 주소라면 Spring Boot를 종료하고, ngrok 주소라면 ngrok 또는 Spring Boot를 종료합니다. MySQL 데이터는 삭제하지 않습니다. 또는 DevTools Request blocking으로 **백엔드 Origin만** 차단합니다.
5. 로컬 검색 페이지를 새로고침합니다. **저장된 데이터**, 마지막 동기화, 읽기 전용 카드·대체 이미지를 확인합니다. 다른 경찰청 검색어로 바꾸면 해당 캐시가 없을 경우 **서버 연결 불가**로 표시됩니다. 자체 등록은 전체 요약을 저장하므로 기존 지역·종류·날짜·정렬 필터를 적용할 수 있습니다.
6. 같은 브라우저 Origin에서 해당 IndexedDB를 삭제한 뒤 서버가 꺼진 상태로 다시 방문하면 최초 방문 오류 상태를 볼 수 있습니다(앱 캐시만 삭제하며 MySQL은 건드리지 않습니다).
7. Spring Boot/ngrok을 같은 주소로 다시 실행하거나 Request blocking을 해제합니다. 각 출처의 **다시 연결** 버튼을 눌러 최신 목록과 동기화 시각으로 바뀌는지 확인합니다.

## 제약 사항

- 기존 Sites 버전 8에 반영했습니다. `/`·`/search`와 JS·CSS 응답은 HTTP 200이며 테스트한 빌드와 일치했습니다. Chrome 자동 검증 도구가 브라우저 URL을 확인하지 못해 실제 렌더링·콘솔 검증은 완료하지 못했습니다. localhost·127.0.0.1·Sites 등 서로 다른 Origin은 IndexedDB를 공유하지 않습니다.
- Service Worker/PWA 셸 캐시를 구현하지 않았습니다. 프론트엔드 페이지 자체를 처음부터 네트워크 없이 불러오는 기능을 의미하지 않습니다. Sites는 열리고 백엔드만 중단된 상황 또는 이미 열린 React 화면에서 동작합니다.
- 상세·정확한 장소·설명·등록 시각은 저장하지 않습니다. 오프라인 검색은 제목·종류·색상·지역·발생 날짜 요약에 한정됩니다. 공개 목록의 상태도 저장 당시 상태이며 실제 보관/반환 여부는 재연결 후 확인해야 합니다.
- 경찰청은 같은 조건에서 연속으로 조회·저장된 페이지만 복원합니다. 캐시에 없는 추가 페이지와 상세 조회는 불가능하며, 더 보기는 재연결 후 사용합니다. 경찰청 필터 공통코드 옵션은 캐싱하지 않습니다.
- API 주소 변경·캐시 만료·브라우저 저장소 삭제/자동 정리/한도 초과 시 이전 기록을 사용할 수 없습니다. 저장은 동기화나 백업을 의미하지 않습니다.

## 발표에 활용할 특징 3가지

1. **출처별 장애 격리**: 네 API 결과를 독립 상태로 다루고, 연결 장애와 인증·입력 오류를 구분해 한 출처의 실패가 다른 최신 데이터를 숨기지 않게 합니다.
2. **개인정보를 줄인 제한적 영속 저장**: allowlist 요약·SHA-256 조건 키·트랜잭션·TTL·개수/용량 정책으로 공개 목록만 관리합니다.
3. **정직한 읽기 전용 복원**: API 우선 조회, 마지막 성공 시각과 오래된 데이터 표시, 재연결 갱신, 쓰기 큐 제외를 통해 오프라인 데이터를 정상 서버 응답처럼 보이지 않게 합니다.
