# 경찰청 공공데이터 캐시와 호출 제한

## 조회 정책

- `GET /api/public-items/lost`, `/found` 목록은 서버 메모리에서 조회 조건·유형·페이지·페이지 크기별로 12시간 재사용한다. 날짜를 생략하면 한국 날짜도 키에 포함하여 자정 이후 전날의 기본 기간을 재사용하지 않는다.
- 기본 페이지 크기는 50건이다. 검색 화면은 분실물·습득물 각각 최대 50건부터 표시하고, 사용자가 더 보기를 선택할 때만 다음 50건을 요청한다. 전체 데이터를 미리 수집하거나 주기적으로 외부 API를 호출하지 않는다.
- 브라우저 새로고침과 재방문은 캐시를 우회하지 않는다. 화면의 새로고침 버튼만 `refresh=true`를 전달한다. 동일 조건·페이지의 실제 조회 시도 후 1분 동안은 서버에서도 추가 갱신을 제한한다. 다른 방문자와도 이 제한을 공유한다.
- 동일 키로 들어오는 동시 요청은 진행 중인 조회 하나를 공유한다. 전체 목록 캐시는 최대 512개 페이지이고, 공간이 부족하면 진행 중인 조회를 제외한 가장 오래 사용하지 않은 항목을 제거한다. 제거된 조건은 다음 방문 때 다시 조회할 수 있다.
- 첫 페이지의 수동 갱신이 성공하면 해당 조건의 추가 페이지 캐시를 무효화한다. 화면도 첫 페이지부터 다시 시작한다. 갱신에 실패하면 기존 목록·추가 페이지·실제 조회 시각을 유지하고 오류와 재시도 가능 시각을 표시한다.
- 외부 오류 시 기존 서버 결과는 조회 후 최대 24시간까지만 제공하며 `stale=true`로 표시한다. 최초 조회 실패도 1분간 재사용하여 연속 재시도로 외부 API를 반복 호출하지 않는다.
- 상세 정보는 기존처럼 외부 API로 조회한다. 지역·분류·색상 공통코드는 기존 12시간 캐시를 유지한다. LOST QUEST 자체 게시글·비공개 질문·인증·반환 데이터에는 이 서버 캐시를 적용하지 않는다.

## 외부 호출 상한

사용자가 확인한 포털 일일 한도는 100,000회다. 앱에서는 아래의 더 낮은 기본값을 적용한다.

| 범위 | 기본 상한 |
| --- | --- |
| 서비스별 60초 구간 | 60회 |
| 서비스별 한국 날짜 하루 | 5,000회 |
| 모든 서비스 합계 진행 중인 요청 | 4회 |

서비스는 분실물(`LOST`), 습득물(`FOUND`), 공통코드(`CODE`)로 구분한다. 목록·상세·공통코드·색상 그룹별 분할 조회·매칭에서 발생하는 실제 HTTP 호출을 모두 계산하며 실패한 외부 호출도 예산을 사용한다. 캐시 응답은 외부 호출 예산을 사용하지 않는다. 상한에 도달하면 외부 호출 전에 중단하고 기존 `EXTERNAL_API_RATE_LIMITED` 오류(503, `Retry-After: 60`)를 반환한다. 재시도 시에도 일일 상한은 다시 검사한다.

필요하면 기존 설정 파일이나 시작 인자로 다음 값을 조정한다. 포털 상한 자체를 앱 상한으로 바로 사용하지 말고, 동일 키를 사용하는 다른 프로그램의 호출량도 고려한다.

```yaml
app:
  police-api:
    traffic:
      per-minute: 60
      per-day: 5000
      concurrent: 4
```

캐시와 호출 횟수는 **단일 JVM 메모리 기준**이다. 서버 재시작 시 초기화되며 여러 서버나 다른 프로그램이 같은 인증키를 쓰는 경우 합산하지 못한다. 현재 단일 서버 전시 환경을 위한 보호 장치이며, 포털 전체 트래픽을 영구적으로 보장하는 분산 제한 장치는 아니다. 포털의 실제 사용량도 함께 확인한다.

## 응답과 브라우저 저장

목록 응답의 `cache`에는 `fetchedAt`, `expiresAt`, `refreshAllowedAt`, `hit`, `stale`, `refreshError`가 포함된다. 조회 시각은 캐시를 읽는 시각으로 갱신하지 않는다. 구버전 백엔드처럼 메타데이터가 없으면 새로고침 버튼을 표시하지 않는다. 새 정책을 운영 서버에 적용하려면 새 백엔드 JAR이 실행되어야 한다.

기존 IndexedDB 오프라인 공개 요약 캐시는 별도의 7일 정책을 유지한다. 서버 캐시가 있어도 브라우저의 시계로 조회 시각을 덮어쓰지 않으며, 서버가 같은 결과를 반환하면 추가 페이지를 삭제하지 않는다. 오프라인 모드는 기존처럼 읽기 전용으로 표시한다. 비공개 본문·확인 정보·토큰은 저장하지 않는다.

## 검증

```powershell
# Java 21, backend 폴더: H2 및 로컬 모의 경찰청 서버 사용
./mvnw.cmd test

# frontend 폴더: 프로젝트의 지원 Node 버전 사용
npm test
npx tsc -b
npm run build
```

`PoliceListCacheTest`, `PoliceApiTrafficGuardTest`, `PublicItemControllerTest`에서 12시간 만료, 1분 갱신 제한, 한국 날짜 경계, 실패 후 보존, 용량 제한, 실제 병렬 HTTP 요청 8개에 대한 외부 호출 1회, 예산 초과 시 외부 서버 미도달을 확인한다. 프론트엔드 API·로더·검색 화면 테스트에서 메타데이터 검증, 실제 조회 시각, 50건 요청, 중복 클릭 방지, 갱신 성공·실패의 추가 페이지 처리를 확인한다. 실제 경찰청 API에 부하를 주거나 업무 MySQL 데이터를 변경하는 테스트는 실행하지 않는다.
